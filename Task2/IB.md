# 1. Управление доступом
**Почему выбрано:** Это наиболее критичная проблема компании, выявленная в ходе аудита.

**Критические риски обнаружены в этой области:**

- BI-системы имеют неограниченный доступ к ПДн (нарушение 152-ФЗ)
- Отсутствие MFA для критических систем (онлайн-сделки, CRM)
- Партнеры могут видеть чужие данные (нарушение конфиденциальности)
- Нет централизованного управления учетными записями

**Бизнес-последствия:**
- Репутационные риски - утечки ПДн могут привести к штрафам и потере доверия клиентов
- Операционные риски - бывшие сотрудники сохраняют доступ к системам
- Регуляторные риски - нарушения 152-ФЗ влекут административную и уголовную ответственность

**Приоритетность:** 
Без контроля доступа все остальные меры безопасности неэффективны. Это базовый уровень безопасности, который нужно наладить в первую очередь.

# 2. Безопасность данных 
**Почему выбрано:** Прямо связано с основным бизнесом компании.
Компания работает с персональными данными клиентов.

**Критические риски обнаружены в этой области:**

- Отсутствие классификации данных.
- Нет шифрования БД на уровне хранения
- BI/AI системы блокированы из-за отсутствия Data Governance
- Нет анонимизации данных для аналитики


# 3. Защита инфраструктуры
**Почему выбрано:** Гибридная инфраструктура (собственный ЦОД + облако) создает риски.

**Критические риски обнаружены в этой области:**

- Отсутствие сетевой сегментации (компрометация одной системы угрожает всем)
- Нет регулярного сканирования уязвимостей
- Базовый firewall не защищает от внутренних угроз
- Масштабируемость: По мере роста компании инфраструктура будет усложняться. Без фундаментальных мер защиты это приведет к неуправляемым рискам.

# 4. Управление инцидентами
**Почему выбрано:** Компания не готова к реагированию на кибератаки.
 Компания реагирует на проблемы постфактум, а не предотвращает их.

**Критические риски обнаружены в этой области:**

- Нет SIEM - невозможно увидеть картину атаки в реальном времени
- Нет плана реагирования
- Не ведутся учет и анализ инцидентов
- Бизнес-непрерывность: При успешной атаке (например, шифровальщик или DDoS) компания может потерять возможность вести бизнес. Отсутствие плана восстановления - риск банкротства.
- Требования регуляторов: 152-ФЗ и отраслевые стандарты требуют наличия процедур реагирования на инциденты.

# 5. Специфические аспекты 
**Почему выбрано:** Отражает уникальные характеристики компании и современные угрозы.
 Актуально из-за:
- Мобильное приложение собственников - кастомное решение без MDM контроля
- Удаленная работа - требует безопасного доступа к корпоративным ресурсам
- Гибридная инфраструктура - требует особого подхода к бэкапам в облаке

 Управление оборудованием - Критично из-за:
- Собственный ЦОД - физическая безопасность не может быть на аутсорсе
- Невозможно управлять тем, что не учтено

Риски утечки при списании - оборудование содержит ПДн клиентов

# Итоговое обоснование:

**Пять разделов выбраны потому, что они:**

- Покрывают все выявленные в аудите критические риски
- Соответствуют профилю компании (обработка ПДн, гибридная инфраструктура)
- Учитывают регуляторные требования (152-ФЗ)
- Отражают текущую зрелость ИБ - на первом этапе необходимо сформировать фундамент
- Поддерживают бизнес-цели 
- Обеспечивают системный подход - от контроля доступа до реагирования на инциденты
